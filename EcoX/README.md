## Purpose

Eco-X is the ecological operating and public-benefit pathway for Eco-Grex, Embedded and Second Cycle. The system is designed to:

- define ecological functions before candidate species or technical components;
- protect intact systems and retain non-intervention as a valid decision;
- represent affected human, non-human, ecological, cultural and future-generation interests;
- create controlled test beds, evidence rooms, FMEA and MRV;
- coordinate place-specific deployment without erasing local authority or viable livelihoods;
- separate reported, measured, derived, reasoned, modelled, aspirational and released states;
- preserve claim scope, uncertainty/limitations, sensitivity and provenance through machine and publication exports.

## Claim identity and release control

Historical local claim IDs are retained, but machine/export identity is namespace-qualified so independent registers cannot collide:

- programme-wide claims: `PRG:CLM-*`;
- Embedded / Bio-Blocks claims: `EMB:CLM-*`.

The canonical rule is `Claim_UID = claim_namespace:claim_id` (`FM-041`). A claim can enter a public machine/package release only when the separate release gate (`FM-042`) is satisfied, including unique Claim UID, evidence state, scope, limitations, sensitivity, approval/public-use fields, applicable gates, `VG-007 = RELEASED`, and verified publication readback.

At R053 the current Eco-X public package state remains **HOLD**. Existing internal `Approved`, `Active`, `Public-safe`, reported or official-source states are not silently reclassified as released.

The canonical workbook specifies `EcoX/evidence/claim_index.csv` and related machine exports. Their schema/state is controlled in the workbook; a repository file is not asserted to exist until GitHub readback verifies it.

## Projection boundary

The projection engine produces **normalised contribution indices** from explicit project inputs: deployment year, ramp, duration, scale, project state, confidence, governance and application variant. These outputs support comparison and planning. They are not direct forecasts of hectares restored, pollutant loads removed, species populations, carbon credits, river condition or reef condition until calibrated with appropriate measured evidence.

Projection exports remain **Modelled** and must retain scenario/year/metric or receiving-system identity, evidence/UQ state, scope and limitations, source/input/formula revision, and any Claim UID / VG-007 package linkage. Missing uncertainty or evidence is not converted to zero.

## Application logic

### Embedded

Land-restoration application family covering substrate, soil, seed/propagation, habitat, corridor, brown-waste and rehabilitation modules. Candidate biological components remain place-specific and review-gated. Fungal/mycorrhizal inoculation is optional, not default; `DO_NOT_INOCULATE` is a valid controlled outcome where evidence or biosecurity conditions do not support release.

### Second Cycle

Water-cycle application family covering capture, separation, filtration, storage, reuse, controlled soaking, safe overflow and monitoring. Second Cycle is not weather control.

### Eco-Grex

Integrated configuration layer combining Embedded, Second Cycle, community capability, governance and evidence functions. Stacked benefits, overlap, maintenance and residual risk are modelled separately.

## Release discipline

No final registration, charity, DGR, ACCU, carbon/biodiversity credit, regulator approval, government adoption, partner confirmation, exact site deployment, field success, ecological performance, hydrological effect, fungal benefit or general recipe validation is implied unless the corresponding evidence, authority and release gates pass and the released artefact is read back.
